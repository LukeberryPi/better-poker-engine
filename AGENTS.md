# Agent instructions

## Git: main is protected — branch, then PR

Never commit to or push `main`, not even a one-line fix. Every change starts
on a branch (`feat/…`, `fix/…`, `chore/…`) and lands through a pull request.
Stacked PRs are fine: base the branch on the one it builds on.

## Plans are working documents — never commit them

Implementation plans, design specs, task checklists and any other
agent-workflow artifact must not be written into the repository. Plan in the
conversation or in a scratch file outside the worktree. Two files are exempt
and stay committed: `adrs.md` (decisions that outlive the change that made
them) and `human-steps.md` (what only a person can do). Everything else about
_how_ a change was made belongs in the PR description.

## No Python anywhere

pokerkit is the behavioral reference, not a dependency. No Python files, no
Python in scripts or CI, and no code generated by running Python. Port by
reading the source.

## Comments: default is none

Do not write a comment. Write one only when something in the code is untrue,
unsafe, or surprising without it. If the name, types, tests, or diff already
carry the point, the comment is noise — delete it.

Ask, in order: can I rename this? can the type / test say it? if both are no,
then a comment.

Never write these:

```ts
// increment the pot
pot += amount;

/** Returns the player id. */
function playerIdOf(view: PlayerView) { ... }
```

A comment earns its place only when it carries one of:

- compatibility or pokerkit-parity behavior that looks wrong but is intended;
- workarounds, gotchas, or non-obvious reasons;
- links to documentation, specifications or ADRs;
- invariants, units, or constraints the names cannot say.

When editing existing code, do not add narration comments describing your
change. A comment that stays is at most **3 source lines**, including the `//`
or `/** */` wrapper. Enforced by `anti-slop/no-long-comments`.

## TypeScript: parse at the boundary, never cast

Data from outside the program — client JSON, PHH files, stored rows — is
parsed once, where it enters, into a named domain type. Past that point the
types are true, so nothing needs to cast, re-check, or widen them.

```ts
// Never: launders the value through unknown.
const action = (await request.json()) as unknown as ClientAction;

// Good:
const action = clientActionSchema.parse(await request.json());
const options = { boards: 2 } satisfies Options;
```

- **Parse, then trust.** Code past the boundary takes and returns named domain
  types — never `unknown`, `object`, or a dictionary of `unknown` / `any` /
  `object` / `{}`. The one exception is an error `cause`.
- **No `typeof` checks.** Branch on domain values instead.
- **Every assertion states its invariant.** An `as` (other than `as const`)
  needs a `// SAFETY:` comment right above it saying what makes it true. Never
  chain assertions (`as unknown as T`).
- **Keep the evidence you have.** Do not annotate a known value with a broader
  type. Let inference keep it or check it with `satisfies`.
- **No reflection escape hatches** (`Reflect.get`, `Reflect.apply`).
- Add an optional property in its own statement, not with
  `...(cond ? { key } : {})`.
- Name a symbol for its domain role, never "shape".
- Make impossible states unrepresentable: discriminated unions over flags and
  nullable fields that only make sense together.

All of these are enforced by the `anti-slop` oxlint plugin in
`tools/oxlint/anti-slop`.

## Engine purity

`packages/better-poker-engine/src` never reads a clock, a random source,
globals, the console, or does I/O. State is immutable plain data: every
transition returns new values and never mutates its inputs. The only file
allowed to touch `crypto` is the random-source adapter. Lint enforces this.

## pokerkit parity

The parity bar is pokerkit at commit `abf7952`: 161 unit tests and 1,170
doctest examples, listed by id in `parity/manifest.ts`.

- Port a unit test with `unitTest(id, body)` and a docstring's examples with
  `doctest(id, (example) => { example(1, …); example(2, …) })`, both from
  `parity/harness.ts`. The ids are a typed union, so a typo does not compile.
  `doctest` fails unless every example number in the docstring ran.
- "Same behavior" means the same accept/reject decision and the same resulting
  values. Python error text and `repr` output are not compared; assert the
  value the example shows instead.
- A doctest that expects `TypeError` becomes a `// @ts-expect-error` line.
- An example with nothing to execute in TypeScript (an `import`) still gets
  its `example(n, …)` call, with the following example asserting through it.
- When a module's port is complete, add its pokerkit source file to
  `parity/required.ts`. CI then fails if any of its ids is missing or red.

## Tests: every assertion must be able to fail

Before adding a test, answer one question: what change to the product code
would make this go red? If you cannot name it, the test is decoration. Then
prove it — break the code and watch the test fail.

- **Never assert on the text of a source file.** Enforced by
  `anti-slop/no-source-text-assertions`.
- **Assert the value the test name promises**, not a proxy that correlates
  with it.
- **A skipped suite is a green suite.** A conditional skip must fail loud when
  an environment variable declares it required. Enforced by
  `anti-slop/no-silent-skip`.
- **Do not drive the same input through the same code twice.**
- **If a test is the only caller of a code path, delete the path.**
- **Drive the real seam rather than a mock.** Enforced by
  `anti-slop/no-module-mocking`.
- **Spend effort by blast radius:** money (chips, pots, payouts) and hidden
  information (hole cards reaching the wrong audience) first, then rule
  correctness, then everything else.
